## 2. 目的・利用者・主要業務の評価

- 目的: 取締役会プロセスと内部監査プロセスを、機密区分と証跡を保った単一の追跡面でつなぐ統制ハブ。既存正本は置換せず、参照・審査・統制・証跡のハブとして位置づける。
- 主要利用者: 取締役 / 監査役等 / 会議体事務局 / 内部監査（担当・レビュー・責任者）/ 主管・被監査部門 / 法務・記録管理 / システム管理者・監査ログ閲覧者。
- 主要業務フロー2本:
  1. 議案受付→招集・出欠→資料パッケージ固定→利益相反→資格・定足数→正式議決→結論Evidence Manifest→議事録→履行タスク→独立確認
  2. 監査ユニバース→リスク評価→年度計画→個別監査→手続・調書→レビュー→指摘→経営回答→是正→独立再検証・再オープン
- 差別化点（MVPで実証すべき）: 議案・決議・監査結論を原子的に封緘するEvidence Manifest、追記型監査ログチェーン、職務分離（作成者≠レビュー者）のサーバ側強制、AI草案の出典必須ガード、利益相反の操作別制御。
